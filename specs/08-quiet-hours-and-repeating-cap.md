## 1. Goal
The user can set one daily quiet window (default 22:00 to 07:00, off by default) during which Standard reminders stop nagging, so nothing re-alerts at 3 am. Separately, the user can turn on "Pause nags while Do Not Disturb is on" (off by default), which pauses the same nags whenever the phone's Do Not Disturb is on right now, whatever turned it on. Nags pause if either is active and resume when neither is. The first alert at a reminder's due time still happens. Prominent reminders are never paused. Critical reminders are not paused by default, and a third setting, "Critical alerts also pause during quiet hours" (off by default), lets the user pause them too. ~~Also, the free tier gains Naggit's second limit: at most 2 repeating reminders before unlock, using the same paywall as Spec 7.~~ Withdrawn 27 Nov 2026: no repeating cap.

## 3. Scope

### A. Quiet hours

Tim's call (26 Nov 2026): the window is a setting the user controls (on or off, start, end), with 22:00 to 07:00 as the starting value only.

**What Due does, and what to copy.** Due has no quiet hours setting. It is not in Due's Settings or Sounds & Alerts screens (`email1-image3.jpg`, `email1-image4.jpg`, `email1-image8.jpg`), and `DO-RESEARCH.md` s. 3 row 23 marks it n/s for Due. Due's equivalent is the system: a Standard alert "Respects Silent mode and Focus", while Critical and Prominent "Always breaks through" a Focus or Do Not Disturb (`due-kb.txt` 419-447). So the Due pattern is: ordinary reminders go quiet at night, important ones still get through. Do copies that split, and takes the feature itself from Naggit, whose listing says "Quiet hours pause re-alerts overnight" (`rev-nag.txt` 94, `DO-RESEARCH.md` s. 2.4). Remindio's version is "label-based Do Not Disturb rules" (s. 2.5); Do has no labels, so it is not copied.

**First fire still alerts.** Naggit pauses "re-alerts", not the reminder itself, and the research reason is "it stops 3 am nagging" (s. 4). So the fire at a reminder's due time alerts normally inside the window. Only nags (Auto Snooze re-alerts) pause. A reminder the user deliberately set for 23:30 rings at 23:30, once, and then waits. This is also the safest reading: a reminder that never alerts is worse than one that alerts once.

Define the two kinds of fire precisely, so every caller agrees:

- **First fire:** the alarm armed for the reminder's current `dueAt`, including a late catch-up of it (`NagSchedule.catchUp`, `SnoozeDue.nextFire`). That covers a new reminder, an edited due, a snooze (snooze moves `dueAt`), Quick Times, the next occurrence of a repeat after Mark Done, and an import. A first fire is never deferred.
- **Nag:** any other fire for the same `dueAt`: `NagSchedule.afterDelivery` in `scheduleAfterDelivery`, `nextAfterAttend` (after Stop on a Prominent), `SnoozeDue.nextFireAfterNagChange`, and a missed nag caught up by `ScheduleResolver` or `rescheduleFromMirrorLocked`. In the mirror, a pending nag is any entry with `nextFireAt != null` and `nextFireAt > dueAt`. A mirrored `nextFireAt == dueAt` is a pending first fire.

**Nags pause, then resume at the window end.** When a nag for a quiet-eligible reminder would be armed at an instant inside the window, arm it at the window end instead, exactly at the end minute (seconds and ms zero). That fire then goes through the normal delivery path, and `NagSchedule.afterDelivery` puts the following nags back on the original anchor grid (`dueAt + k * interval`), so the cadence does not drift. The notification already in the shade from the last alert stays there; Do does not dismiss or re-post it during the window. Log each deferral as `DoAlarm quiet-defer id=<id> planned=<epoch ms> at=<epoch ms>` (no title).

**Which reminders pause.** Keyed on the reminder's requested `alertLevel` (Spec 5), not the effective one after a fallback. The same rule applies to quiet hours and to following Do Not Disturb (section 3A2):

- `STANDARD`: nags pause.
- `CRITICAL`: by default ignores quiet hours and following Do Not Disturb, like Due's Critical breaking through Focus. Tim's call: this is a setting, "Critical alerts also pause during quiet hours" (off by default). When it is on, Critical nags pause exactly like Standard ones, for both the window and following Do Not Disturb.
- `PROMINENT`: always ignores quiet hours and following Do Not Disturb, like Due's Prominent. Not configurable. Its hold-until-attended loop and the nag after Stop carry on as in Spec 5.

Put the rule in one place: `QuietHours.exempt(level, config): Boolean` is true for `PROMINENT`, true for `CRITICAL` when `criticalPauses` is false, and false otherwise. A Prominent reminder that falls back to Critical stays exempt (requested level Prominent). A Critical without DND access (Spec 5 fallback) follows the Critical setting. Whether Android's own Do Not Disturb then silences an exempt alert is the Spec 5 fallback, not this spec. There is no separate per-reminder quiet toggle: the alert level is the override, which keeps Do to one concept, as Due does.

**The window.** One daily window, stored as start and end minutes from local midnight, minute precision. Default 22:00 to 07:00, **off** by default. The window is `[start, end)` in local wall time: a nag at exactly 22:00 is deferred, a nag at exactly 07:00 is not.

- `start > end` crosses midnight (22:00 to 07:00): inside when local time is at or after start, or before end.
- `start < end` is a same-day window (for example 13:00 to 14:00, assumed allowed).
- `start == end` is not allowed. The Settings picker refuses it with a plain message and keeps the old value. The debug hook rejects it.

The window end for an instant `t` inside the window is the next local `end` time after `t`, built with `ZonedDateTime` in `ZoneId.systemDefault()`. Put all of this in one pure object, `alarm/QuietHours.kt`, alongside `NagSchedule`, with `data class QuietConfig(enabled, startMinute, endMinute, followDnd, criticalPauses)`, `fun inWindow(t, config, zone): Boolean`, `fun windowEnd(t, config, zone): Long?`, `fun exempt(level, config): Boolean`, `fun placeNag(planned, alertLevel, config, zone): Long` (returns `planned` when the window is off, exempt, or outside the window), and `fun holdForDnd(alertLevel, config, dndActive): Boolean` (true only when `followDnd` is on, `dndActive` is true and the level is not exempt). `placeNag` handles only the window, because Do Not Disturb has no known end time; Do Not Disturb is checked at fire time and on its change broadcast (section 3A2).

**DST.** Local wall time rules. If the end time falls in a spring-forward gap, use `ZonedDateTime.of` default resolution (moved later by the gap length). In an autumn overlap, keep the default earlier offset. The window can be an hour longer or shorter on a transition night; that is expected. Perth has no DST, so this is unit-tested only, with a DST zone such as `Australia/Sydney` from the JDK rules (assumed test zone; no transition dates are hard-coded).

**Time zone and clock changes.** The window follows the device's current zone, like Due's wall-clock repeats in Spec 4. `Scheduler.onExternalClock` already runs on boot, `TIME_SET` and `TIMEZONE_CHANGED`. After its existing work, it runs the quiet reconcile (below), so a nag held for "07:00 in the old zone" is re-placed for the new zone.

**Reconcile.** Add `Scheduler.reconcileQuietHours()` (guarded by the same mutex). It reads the config and the live Do Not Disturb state once. For each mirror entry that is not `pendingDone`, not `awaitingAttend`, and has a pending nag:

- If the entry is `dndHeld` (section 3A2) and `holdForDnd` is now false (Do Not Disturb off, following turned off, or the level now exempt): `raw = now`, clear `dndHeld`, log `DoAlarm dnd-release id=<id> at=<epoch ms>`.
- If the entry is `dndHeld` and `holdForDnd` is still true: leave it armed at its next anchor.
- Otherwise: `raw = NagSchedule.nextAnchorStrictlyAfter(dueAt, nagMinutes, now)`.

Then `QuietHours.placeNag(raw, ...)`; if it differs from the stored `nextFireAt`, cancel, upsert the mirror and arm the new time (a released nag armed at `now` fires at once through the normal path). Pending first fires are left alone. Run it after any Settings change to the quiet hours section (all three switches and both times), after `SET_QUIET_HOURS`, on `ACTION_INTERRUPTION_FILTER_CHANGED`, at the end of `onExternalClock`, and after `replaceAll` / `mergeAll` (Spec 7 Replace can bring in settings). Effects: turning quiet hours on at 23:00 moves a 23:05 nag to 07:00; turning it off at 01:00 brings a held 07:00 nag back to the next anchor; widening or narrowing the window re-places held nags; turning "Critical alerts also pause" on defers Critical nags in the window, and turning it off brings them back to the next anchor; Do Not Disturb going off releases held nags at once (or to the window end if the window is on and active).

**Reboot and direct boot.** Fires before first unlock use the `MirrorEntry` path, which cannot read `do_settings` (credential-protected). So quiet hours lives in a new `QuietHoursStore` on device-protected storage (prefs file `do_quiet`, keys `quiet_enabled` (false), `quiet_start_min` (1320), `quiet_end_min` (420), `quiet_follow_dnd` (false), `quiet_critical_pauses` (false)), the same pattern as `HealthStore`. A missing key reads as its default. `rescheduleFromMirrorLocked` and `rescheduleAllLocked` apply `placeNag` to any pending nag whose stored time has passed (the "fire now" catch-up) and to the result of `ScheduleResolver.resolve` when the mirror says it is a nag. A first fire missed while the phone was off still alerts on catch-up, even inside the window. Add `do_quiet.xml` to both Auto Backup rule files with the `device_sharedpref` domain, so a restored phone keeps all five settings (Android Auto Backup docs as cited in Spec 7; Jim confirms the domain name against that page).

**Snooze.** Snooze moves `dueAt`, so the snoozed time is a first fire and alerts, even inside the window (the user chose that time). Its later nags pause. Snooze all is the same per reminder. No snooze option is changed.

**Repeats.** Each occurrence's due is a first fire. Mark Done on a repeating reminder places the next occurrence by the Spec 4 maths, untouched by quiet hours; if that due falls in the window it still alerts once, then its nags pause. Minute and hour repeats are the same: they advance only on Mark Done (Spec 4), so quiet hours never skips or shifts an occurrence. Quiet hours does not write `dueAt`, `patternDueAt`, or any repeat column.

**Health and late fires.** `AlarmReceiver` reports `scheduled` from the alarm extra, which is the deferred time, so a nag held to 07:00 and fired at 07:00 is not a Spec 6 late fire. The health one-minute test is a first fire and is not affected. No health row is added for quiet hours.

**Alarm engine.** No change to `AlarmScheduler` or `setAlarmClock()`. Quiet hours only feeds a different time into the existing `alarms.schedule(id, at)` calls. One alarm per reminder, as now.

**Settings.** On `SnoozeSettingsScreen`, after the default alert level and the full-screen / DND rows and before Health check, add a "Quiet hours" section, in this order:

1. Switch "Quiet hours" (off), then "Starts" (22:00) and "Ends" (07:00), each opening the existing time picker already used for At Time snooze, and shown in the device time format. The start and end rows stay editable while the switch is off.
2. Switch "Pause nags while Do Not Disturb is on" (off). Subtitle, assumed copy: "Follows your phone's Do Not Disturb, however it was turned on."
3. Switch "Critical alerts also pause during quiet hours" (off). Subtitle, assumed copy: "Applies to quiet hours and Do Not Disturb. Prominent alerts are never paused."

Section caption, assumed copy: "Pauses repeat alerts during these hours. The first alert still comes. Critical alerts are not paused unless you turn that on below, and Prominent alerts are never paused." Australian English on every new string. Each switch writes `QuietHoursStore` and runs the reconcile. The Do Not Disturb switch needs no permission prompt: reading the live filter needs no notification policy access.

**Backup.** Add the five values to `PortableSettings` and to the schema 1 `settings` object as optional keys `quietEnabled`, `quietStartMinute`, `quietEndMinute`, `quietFollowDnd`, `quietCriticalPauses`. Each key is optional on its own: a missing key leaves that one setting unchanged. `BackupCodec.decodeSettings` currently returns null when any field is missing, so the new keys must be optional: a schema 1 file from Spec 7 without them imports as before and leaves the current quiet settings unchanged. An out-of-range or equal start and end in a file is ignored for those keys only. `schemaVersion` stays 1. Replace applies them (portable settings); Merge does not (Spec 7 call 6).

**Free or unlock.** Free. Spec 7 call 1 makes every shipping feature available in the free tier, and the cap is the only limit. Naggit puts quiet hours in Pro (`rev-nag.txt` 94). Following Do Not Disturb and the Critical setting are free too. See section 7.

### A2. Pause nags while Do Not Disturb is on

**What and why.** Tim's call (26 Nov 2026): as well as the window, Do can follow the phone's own Do Not Disturb, so a Sleeping rule to 07:15, a Bedtime mode or a manual toggle all pause nags without a second schedule to keep in step. Due has no such setting; its Standard alert simply "Respects Silent mode and Focus" (`due-kb.txt` 419-447), and Remindio has "label-based Do Not Disturb rules" (s. 2.5). Do copies the Due split (ordinary reminders go quiet, important ones break through) and pauses the nags instead of letting them pile up silently.

**Live state only.** Do reads `NotificationManager.getCurrentInterruptionFilter()` (API 23, below minSdk 26, so no version check). Do Not Disturb counts as **on** for `INTERRUPTION_FILTER_PRIORITY`, `INTERRUPTION_FILTER_NONE` and `INTERRUPTION_FILTER_ALARMS`, and **off** for `INTERRUPTION_FILTER_ALL` and `INTERRUPTION_FILTER_UNKNOWN` (unknown must never pause a nag). Reading the filter needs no notification policy access. Do must **not** call `getAutomaticZenRules()`, read `getNotificationPolicy()` for scheduling, ask for `ACCESS_NOTIFICATION_POLICY`, or try to predict when Do Not Disturb ends. No new permission is added for this feature (Spec 5's existing DND access request for Critical is unchanged and not relied on here). Wrap the read in `alarm/DndState.kt` (`fun filter(): Int`, `fun isActive(): Boolean`), with a debug-only override (section 3C) so JVM tests and the runner can simulate the state; release builds always read the real filter.

**When it pauses.** Off by default (`quiet_follow_dnd`). When on, a nag for a non-exempt reminder (same `QuietHours.exempt` rule as the window, including the Critical setting) does not alert while Do Not Disturb is on. First fires still alert, as for the window: a reminder due during Do Not Disturb alerts once (Android may silence it; that is the system), then waits. Nags pause if either the window or Do Not Disturb applies, and resume only when neither does.

**Re-check on each nag fire.** Do Not Disturb has no end time Do can know, so the check happens when the nag fires. In `Scheduler.onFire` (both the unlocked and the mirror branch), before `notifications.show`, if the fire is a nag (the mirror rule in section 3A: stored `nextFireAt > dueAt`) and `QuietHours.holdForDnd(level, config, DndState.isActive())` is true: do not show, re-post or dismiss anything (the last notification stays in the shade), set the mirror entry's new field `dndHeld = true`, arm `QuietHours.placeNag(NagSchedule.nextAnchorStrictlyAfter(dueAt, nagMinutes, actual), ...)`, and log `DoAlarm dnd-hold id=<id> scheduled=<epoch ms> next=<epoch ms>` (no title). `AlarmReceiver` still logs its `DoAlarm fire` line and Spec 6 health still records the arrival, because the alarm itself was on time. So a held reminder keeps a cheap alarm on its nag grid, and if the process is dead when Do Not Disturb ends, the nag resumes at the next anchor at the latest.

**Resume on the broadcast.** `ACTION_INTERRUPTION_FILTER_CHANGED` is delivered only to runtime-registered receivers (and, from Android 10, to manifest receivers of apps with DND access, which Do does not rely on). Register a receiver in `DoApp.onCreate` (through `AppContainer.start`) with `ContextCompat.registerReceiver(..., RECEIVER_NOT_EXPORTED)`, for the life of the process. On each broadcast it logs `DoAlarm dnd filter=<n> active=<b>` and runs `reconcileQuietHours()`, which releases held nags at once when Do Not Disturb goes off (section 3A Reconcile). Do Not Disturb going on needs no work: the next nag fire holds itself. No manifest receiver is added for this action. `onExternalClock` (boot, `TIME_SET`, `TIMEZONE_CHANGED`) already ends with the reconcile, so a held nag is released after a reboot if Do Not Disturb is off by then.

**Mirror field.** `MirrorEntry` gains `dndHeld: Boolean = false`, written with `put("dndHeld", ...)` and read with `optBoolean("dndHeld", false)`, the same pattern as `awaitingAttend`, so an older mirror file still loads. It is cleared on release, on any new first fire for the entry (new `dueAt`, snooze, Mark Done on a repeat), and when the entry leaves the mirror. This is a mirror file field, not a Room column.

**Interplay with the window.** If a held nag's next anchor falls in the window, `placeNag` moves it to the window end. If the window ends while Do Not Disturb is still on, the window-end fire is a nag and holds itself. If Do Not Disturb goes off inside the window, the release goes to the window end. Either way, a nag alerts only when neither applies.

### B. Free-tier repeating cap (withdrawn 27 Nov 2026)

**Removed.** Tim decided on 27 Nov 2026 that the free tier has one limit, `FreeTier.ACTIVE_REMINDER_CAP = 5`, counting every not-done reminder whether it repeats or not. Editor save goes back to the list straight away, as on main. A unit test checks that a free user can hold 5 repeating reminders and that the sixth reminder of any kind is blocked by the active cap only.

## 6. Risks
- **Tim's phone already has a Sleeping DND rule (22:00 to 07:15).** Android DND may silence Standard first fires in the window anyway, and the 07:00 resume can land inside DND until 07:15. That is the system, not a defect; with "Pause nags while Do Not Disturb is on" turned on, the 07:00 nag holds and resumes when DND ends. Mark scores from logcat, and the runner records the DND state.
- **The runner changing Tim's Do Not Disturb.** `cmd notification set_dnd off` would end a manual DND or override the Sleeping rule. The runner only uses the real path when DND was off at the start, and turns it back off in `finally`; otherwise it simulates.
- **Process dead when Do Not Disturb ends.** `ACTION_INTERRUPTION_FILTER_CHANGED` reaches only a live, registered receiver, so a held nag can wait up to one nag interval after DND ends (the re-check at the next anchor). Long nag intervals make that gap longer. Accepted; the runner cannot kill the process on Samsung reliably (`am kill` checks are RECORD).
- **Unknown filter.** `INTERRUPTION_FILTER_UNKNOWN` is treated as off, so an unreadable state can never stop a reminder nagging.
- **Samsung modes.** Samsung Sleep or Bedtime modes that turn on DND show up as a non-ALL filter and pause nags; modes that only mute sounds do not. Recorded, not changed.
- **A burst at the window end.** Every held Standard nag resumes at the same minute. Spec 2's grouping and silent summary should absorb it, but a morning with many overdue reminders will be noisy. Recorded, not changed here.
- **First fire versus nag classification.** If a caller labels a fire wrongly, a first fire could be silenced or a nag could ring at 3 am. Keeping the rule in one place (mirror `nextFireAt == dueAt` means first fire) and the unit tests are the mitigation.
- **Direct boot.** If the quiet setting were in `do_settings`, fires before unlock would ignore it. The device-protected `QuietHoursStore` avoids that. A missing or unreadable store must mean "off", never a crash.
- **Zone changes while a nag is held.** Without the reconcile at the end of `onExternalClock`, a held nag would keep the old zone's 07:00. AT-11 is unit-only because the runner must not change the zone.
- **Backup decode.** `decodeSettings` is strict today; making a new key required would break every Spec 7 backup. The optional-key rule and its unit test cover this.
- **Edit save returning a result.** `Scheduler.update` and `ReminderViewModel.update` are used by the editor and by `APPLY_QAT`. Changing the return type must not change their saved behaviour; existing tests must still pass.
- ~~**Cap surprise.** A free user with two repeating reminders who types "every day" gets the unlock screen instead of a saved reminder. That matches the Spec 7 active cap behaviour and Naggit's split, but the copy does not say why. A reason line is a later, separate change.~~ Withdrawn with the cap.
